# Connector Credentials — what each connector needs to go live

> Source of truth for env var **names** is `src/lib/integrations/connectors.ts`
> (`requiredEnv` per connector). This doc explains the founder setup behind each.
> **No secret values are stored in the repo.** Until these are set, every
> connector shows **Not Connected** / **Ready for Authorization** and performs no
> external calls.

Callback base (OAuth connectors): `https://<prod-domain>/api/integrations/{id}/callback`.

| Connector | Auth | Env vars (names only) | Provider-side setup |
|---|---|---|---|
| **GitHub** | OAuth2 | `GITHUB_OAUTH_CLIENT_ID`, `GITHUB_OAUTH_CLIENT_SECRET` | Create a GitHub OAuth App (or GitHub App). Callback `/api/integrations/github/callback`. Scopes: `read:user`, `repo`. |
| **Gmail** | OAuth2 (google) | `GOOGLE_OAUTH_CLIENT_ID`, `GOOGLE_OAUTH_CLIENT_SECRET` | Google Cloud project → enable Gmail API → OAuth consent screen → Web client. Scopes: `gmail.readonly`, `gmail.send`. |
| **Google Calendar** | OAuth2 (google) | (shares the Google vars above) | Same Google project → enable Calendar API. Scope: `calendar.events`. |
| **Slack** | OAuth2 | `SLACK_CLIENT_ID`, `SLACK_CLIENT_SECRET`, `SLACK_SIGNING_SECRET` | Create a Slack App → OAuth & Permissions. Bot scopes: `channels:read`, `chat:write`. Signing secret for inbound verification. |
| **Webhooks** | Signed | `WEBHOOK_SIGNING_SECRET` | Platform-level HMAC secret; per-user endpoint secrets are generated by the app. No third-party OAuth. |
| **Supabase** | API key (per-user) | none at platform level | Connects a user's **own** Supabase project. The user supplies a project URL + key at connect time (must be encrypted at rest — see Phase 6 design §4/§7). No founder env var. |
| **Vercel** | API key (per-user) | none at platform level | Connects a user's **own** Vercel account/project via a Vercel access token supplied at connect time. No founder env var. |

## Capabilities prepared per connector

Read = runs directly once connected. **Write = always requires founder approval** (routed through the Phase 2 approval + audit engine).

- **GitHub** — list_repos (read), list_issues (read), create_issue (write)
- **Gmail** — list_messages (read), send_message (write)
- **Google Calendar** — list_events (read), create_event (write)
- **Slack** — list_channels (read), post_message (write)
- **Webhooks** — list_endpoints (read), send_event (write)
- **Supabase** — db_health_check, migration_verification, public_table_inspection, rls_diagnostics (all read)
- **Vercel** — deployment_status, production_url_verification, build_status, env_var_presence (all read)

## Token refresh

OAuth connectors (google / github / slack families) use
`src/lib/integrations/token-refresh.ts`:
`getValidAccessToken(userId, provider, family)` returns a valid token, refreshing
via the `refresh_token` grant when expired and marking the connection
**Authorization Expired** if refresh fails. Dormant until the env vars above are set.

## Status meanings (dashboard)

- **Not Connected** — platform credentials not set (or per-user key not added).
- **Ready for Authorization** — framework ready; awaiting authorization.
- **Connected** — authorized and active.
- **Authorization Expired** — token expired and refresh failed; re-authorize.

## Founder actions to activate (summary)

1. Decide which connectors to enable.
2. Create the provider-side OAuth app(s) and set the env vars above in Vercel (Production + Preview).
3. Confirm the production callback domain.
4. Decide the Supabase/Vercel per-user key handling + at-rest encryption (Phase 6 design §4/§7).
5. Approve enabling live OAuth authorization (not enabled in this PR).
